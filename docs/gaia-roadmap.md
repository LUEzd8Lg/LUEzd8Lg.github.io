# 盖亚世界观 · 网站实用性路线（v2）

> 依据：`世界观库/打印版/盖亚世界观·设定全集.docx`（41 份底本 + 总索引）
> 对照当前站点：`index.html` / `app.js` / `data/manifest.js` / `data/merged.js` / `server/index.js`
>
> **硬约束（v2 修订）**：这个站点的本职是 **放文件、查文件**。
> 不改后端、不改数据格式、不新增业务系统、不做在线创作/协作/审批流。
> 路线只围绕两件事：**把文件放对地方**，和**让人查得到、看得懂、读得顺**。

---

## 路线总纲（一句话）

> **第一优先是把 41 份底本变成站内可读的「文件条目」；其余所有改动只允许发生在"展示层"——渲染、索引、导航、检索，绝不新增需要维护的数据结构或后台流程。**

这条约束直接砍掉了 v1 里的第三阶段（创作平台、冲突检测、审批流），也把「正典层级」这类**新概念**降级为**可选的展示字段**（数据里没这字段也照常跑）。

---

## 0. 现状差距（为什么需要这份路线）

| 维度 | 文档/母本里有 | 站点现状 | 差距 |
|---|---|---|---|
| 正典层级 / 版本裁决 | 文档里写明「冲突裁决顺序」和 3 处作者笔误 | 「正典」在站点里完全不存在 | 旧稿新稿可能同时出现，读者不知哪版为准 |
| 纪年 | 「新历 = 公元 − 2312」+ 常用锚点速查表 | 有「纪年换算」弹窗，但只是 2312 硬编码，且负语文案口径不同 | 缺锚点表、缺「红月前 X 年」表达 |
| 分组 | A–F 组（正文底本 / 洲级叙事 / 势力 / 专题 / 数据表 / 本库） | 5 个分类：异常 / 组织 / 神祇 / 纪元 / 世界史 | 两套组织方式没有对应关系 |
| 数据 | 41 份底本 | `data/merged.js`：异常 0、神祇 0、纪元 0、世界史 0，**组织 1** | 内容几乎没进站 —— **这是第一问题** |
| 下载 | 文件本来就是要给人拿走的 | `exportEntry()` 写好了，但全站没有任何按钮调它 | 文件进得来、出不去 |

**一句话结论**：站点的框架已经齐全且不缺零件，缺的是**文件本身没装进去**（4/5 分类是空的）；其次是**已经写好的下载功能没接上按钮**。两者都在展示层，不需要动结构。

## 1. 三阶段路线（全部是展示层改动）

### 阶段一：把 41 份底本装进来（P0，最高优先）

> 目标：站点从「空壳」变成「文件入口」。这是实用性提升最大的一段，也最机械。
> **当前 `data/merged.js`：异常 0 / 神祇 0 / 纪元 0 / 世界史 0 / 组织 1。5 个分类里 4 个是空的。**

#### 1.1 底本导入管线（复用已有脚本，不改后端）
- `tools/extract-docx.ps1` 已能 docx → JSON，思路正确，只是硬编码了 `世界观目前\` 等旧目录。
- 改造为：`tools/extract-docx.ps1 -Source "C:\...\世界观库" -Out data/`。
- **只补三个已有模式的字段**（不新增数据结构）：`source`（原始 docx 路径，已有字段）、`tags`（已有）、`era`（已有）。
- 产出仍写进现有 `data/*.json` → `data/merged.js` 的流程，**数据格式一个字不变**。

#### 1.2 补齐五类数据（现状是 4 空 1 有）
- 按文档 A–F 组把 41 份底本分别落到 anomalies / organizations / deities / eras / timelines 五个现有分类里。
- 目标不是「写得漂亮」，是**至少每条底本在站内有一个可打开的条目页**。

#### 1.3 B 组洲级叙事：接上已有的四张洲图
- 文档明确「B 组细节远多于世界史」，且仓库里已经有 `data/timeline/中州.png|北州.png|东洲.png|南洲.png`。
- 用现有 `renderList` / `renderEraGrouped` 的渲染路径，把这些洲图挂到对应条目上即可，**不需要新路由**。
- 时间线交叉链接：点时间线上的年份 → 跳到当年所属条目（纯前端 `scrollIntoView` / hash，无新逻辑）。

**阶段一验收**：随便点开站内任意一个分类，都能看到真实文件内容；输入任意一个盖亚专有名词，能命中对应条目页。

### 阶段二：检索与导览（P1，纯展示层）

> 目标：文件有了，要**查得到、找得快**。全部在现有 `renderSearch` / `renderList` / `#/health` 上做增量。

#### 2.1 纪年换算修正（改现有弹窗，不新增概念）
- 现有弹窗硬编码 2312，但文档明确口径是 **新历 = 公元 − 2312**，并附「常用锚点速查表」。
- 弹窗里补上锚点表：白曐坠中州（前 3000）→ 埃尔德融入七门（公元 0）→ 红月政府成立（2312 / 新历 0）→ ECO 成立（2342 / 30）…… 点锚点跳对应条目。
- 负年表达：文档用「红月前 X 年」，现弹窗文案叫「红月纪元之前」，统一成文档口径。
- 数据现成、纯前端一处改。

#### 2.2 正文年份悬浮换算
- 沿用弹窗的换算函数，在详情页正文里识别 `公元 X 年` / `新历 X` / `前 X 年`，悬浮显示另一套纪年。
- 纯展示层，不改正文存储。

#### 2.3 完整度看板接上文档的「九、档案完备度」表
- `#/health` 已有一半骨架；把文档那张表（势力 / 档案 / 字数 / 状态）的**字数与状态两列**接进去。
- 这是文件覆盖度的直接反馈——作者一眼知道哪份底本还是空壳。

#### 2.4 文件清单视图（放文件的站该有的东西）
- 在现有分类页上加一个「文件清单」切换（点一下切表格视图）：文件名 / 原始 docx 路径（`source` 字段已有）/ 字数 / 更新时间 / 下载。
- **目的**：让这个站点对"放文件"这件事本身负责——知道有哪些文件、对应哪条条目、谁更新的。
- 注意：现有的 `exportEntry(cat, entry, format)` 函数**写了但没接到任何按钮上**（全站 grep 只有定义处），这里正好接上作「下载」入口。

**阶段二验收**：任意年份都能换算；打开分类能切到文件清单；健康看板能看到哪份底本还没填。

### 阶段三：只做"可选标注"，不碰流程（P2，可做可不做）

> 目标：让读者读到互相矛盾的旧稿时不迷路。**只加展示字段，不加审批流、不做冲突检测工具。**

#### 3.1 可选的两个展示字段（数据里没有也照常跑）
- `supersededBy`：被哪份新文件覆盖 → 详情页顶部挂黄色「此稿已被《XXX》覆盖」横幅并链到新稿。
- `status`：`canon|draft|deprecated` → 列表卡片角标。
- 关键点：**字段缺失时渲染逻辑走原分支**，所以这个改动可以随时上线、随时回退，不影响现有数据。
- 文档里的「正典层级」不做成页面——它是一段叙述，放进现有 `#/glossary`（术语索引）里作为一条词条即可。

#### 3.2 已知笔误做成术语索引里的一条
- 文档「三个已知的作者笔误」→ 术语索引里一条「已知勘误」词条，列出正确写法。
- 搜索命中笔误词时，结果顶部给黄条提示（纯 `renderSearch` 增量）。

#### 3.3 交叉引用双链
- 正文里出现的其它条目名（「塞拉芬·雷恩」「白曐」「七门」）自动变成链接 + 悬停预览。
- 这是 41 份底本互相引用、读者点不过去这个痛点的唯一解——**仍是纯渲染层**：渲染时扫一遍标题词表做替换，不改存储。

## 2. 优先级与理由（为什么是这个顺序）

| 顺序 | 事项 | 理由 |
|---|---|---|
| 1 | 底本导入（阶段一） | 站点当前 5 分类里 4 个是空的，**这是最大的「不可用」**，且不需要任何新概念 |
| 2 | 纪年换算修正 + 年份悬浮 | 改造成本最低、全站最高频的一次换算 |
| 3 | 文件清单视图 + 接上早已写好却没挂按钮的下载函数 | 这是"放文件的站"的本职 |
| 4 | 完整度看板接文档的表 | 让文件覆盖度可见，指导下一步该补哪份 |
| 5 | 可选标注字段 + 双链 | 让旧稿不迷路，工程量大，放最后 |

**推后或不做**：在线创作 / 协作编辑 / 审批流 / 冲突检测工具 / 多语言 / SSR / 真实后端数据库。这些都会让站点**从「放文件」变成「跑系统」**，与约束冲突。

## 4. 第二轮（本轮）：文库 —— 绕开 shell 的导入路径

**问题**：本机 shell 仍完全不可用（`pwsh`/`node` 启动即崩 `3221225794`），任何导入脚本都跑不了。

**解法**：不跑脚本，直接把 `世界观库/*.md` 原样放进站点，前端读取渲染。这既绕开了 shell，也最符合「站点只放文件」的定位。

| # | 交付项 | 说明 |
|---|---|---|
| 1 | **新增路由 `#/library`** | 文库索引：11 份文档一览，已入档可点开，未入档标「待导入」 |
| 2 | **新增路由 `#/library/:id`** | 站内阅读原文 + 「下载源文件 (.md)」 |
| 3 | **`mdToHtml()` 渲染器** | 自写极简 Markdown→HTML：标题 / 表格 / 引用 / 列表 / 代码块 / 分隔线 / 行内格式，全部用站点现有 CSS 变量 |
| 4 | **已入档 3 份** | `00·总索引与正典层级`、`01·世界总纲`、`07·纪元与纪年基准` |
| 5 | **导航入口** | 顶部导航 + 侧边栏各加「文库」；首页 A–F 卡片改指向文库 |

**为什么先选这 3 份**：`00` 是「先读这个」，`01` 是地基，`07` 是「查年份必用」。三份合起来覆盖「哪条算数 / 世界怎么运转 / 今年是哪年」三件事。

## 7. 第三轮：转向粉丝向（本轮回过头修的方向）

**判断修正**：这是**面向读者的 SCP 式粉丝站**，不是作者工作台。
上一轮把「正典层级 / 已知勘误 P1–P3 / 待补清单」摆进主导航和公开页面，等于把后台摊给读者看 —— SCP 绝不会在条目页写「作者这里写错了」。

### 已做的调整

| # | 调整 | 之前 | 现在 |
|---|---|---|---|
| 1 | **主导航** | 首页/分类/思维导图/术语/正典层级/文库（6 项，编务混在其中） | 首页/分类/**设定中心**/术语索引/**随机观测**（读者向） |
| 2 | **侧边栏** | 档案分类 + 档案馆工具 + 用户操作 + 快捷操作 | 档案分类 / **探索**（随机观测、导图、设定文献、档案夹、纪年）/ 用户操作 |
| 3 | **「正典层级」改名「设定中心」** | 标题「同一件事有三种说法看序号小的」——纯编务口吻 | 「盖亚的全部正典文献 · 按用途分组，告诉你从哪里开始读」 |
| 4 | **冲突裁决顺序 + 已知勘误** | 公开平铺在页面正文 | 收进 `<details>` **「编务附注」**，默认折叠，标注「不属于设定」 |
| 5 | **「文库」改名「设定文献」** | 含矛盾清单/待补清单/勘误 | 这三份标 `internal`，**读者不可见**，管理员可见；直连 URL 也拦 |
| 6 | **A–F「F 组」** | 「本库自身」列着矛盾/待补 | 改名「总纲与索引」，只列读者需要的 6 份 |
| 7 | **措辞** | 「待导入」「N 份在档」「41 份底本」 | 「整理中」「N 篇」「按用途分组」 |

**核心原则**：**作者的后台不该出现在读者的视野里。** 编务内容不是删除，而是折叠或按权限隐藏 —— 存档没丢，读者不受干扰。

### 建议的下一批粉丝向功能（等你挑）

| 优先级 | 功能 | 说明 |
|---|---|---|
| 高 | **条目评分（+1 / -1）** | SCP 的标志性互动。顶部显示「评分 +23」，登录后可投，localStorage 存 |
| 高 | **随机页** | 已有「随机观测」，但可做得更像 SCP 的 random page：直接跳一篇随机档案 |

| 中 | **系列/迭代阅读** | 同一档案的多份「附录」「实验记录」按顺序读 |
| 低 | **阅读模式（无侧栏沉浸）** | 详情页已有字号/TOC，再加一个全屏沉浸开关 |

> ⚠ 前提仍是**内容**：现在站内只有 1 条真实档案（红月政府）。评分、标签云、随机页都建立在「有东西可读」之上。

## 8. 第四轮：条目评分（SCP 式 +1 / -1）

粉丝站最强的参与感来源，且不依赖内容量 —— 只有一条档案也能用。

| # | 交付项 | 说明 |
|---|---|---|
| 1 | **`RATINGS` 模块** | `localStorage` key `wa_ratings_v1`，结构 `{ [cat:id]: { up:[user], down:[user] } }`。按账号去重：同方向再点＝取消，点反方向＝改票 |
| 2 | **详情页评分条** | ID 行内 `▲ 分数 ▼`，正分绿、负分红、零分灰；投票后即时更新，不刷新页面 |
| 3 | **列表卡片角标** | 有票的条目在卡片底部显示 `▲ +N`，悬停看「好评 N · 差评 N」；零票时仍显示字数 |
| 4 | **音效联动** | 投票复用现有 `SFX.favor()` / `unfavor()` |

**设计取舍**：
- **游客也能投**（记为 `__guest__` 一票），降低参与门槛 —— 与站内收藏/已读的既有策略一致。
- **不做五颗星**，只做 +1/-1：SCP 的评分就是单值，且更容易形成「争议条目」的讨论氛围。
- **改票不加权**：一人一票，反方向投票等于换边，不产生 -2。

### 诚实的限制
评分存在**本地浏览器**，换设备/清缓存即丢失，也无法跨用户聚合 —— 现在看到的分数只反映「本机投过的票」。要做到全站真实分数，需要后端或 GitHub Contents API 持久化（站内已有 `CloudSync` 的 PAT 机制可复用，但那是用户自己的仓库）。

## 9. 第五轮：视觉强化（炫酷但不失控）

站内已有入场交错、头图视差、印章旋转、CRT 叠层、boot 序列等动画，所以本轮**不重复堆叠**，只补 5 个有辨识度的效果。

| # | 效果 | 实现 | 观感 |
|---|---|---|---|
| 1 | **动态胶片颗粒** | `body::before` 噪点层加 `grainShift` 关键帧（1.6s、4 段跳变） | 全站像在轻微「呼吸」的银盐胶片，不再是死图 |
| 2 | **编号故障抖动** | 卡片悬停时 `.ec-id` 触发 `idGlitch`：红／白双向位移 + 字影 | 扫描到档案编号时像信号不稳，SCP 味很足 |
| 3 | **路由转场** | `#view-container` 每次切换重放 `routeEnter`（淡入 + 上移 + 轻微模糊） | 页面切换不再是硬跳，有「换卷宗」的呼吸感 |
| 4 | **详情页解封扫描** | 详情卡片顶部一道高光横扫到页尾（1.25s 一次） | 打开档案时像被扫描仪解封 |
| 5 | **标题解码** | `decodeTitle()`：乱码字符逐字解出目标标题，末尾闪烁光标 | **本轮最强的一击** —— 档案标题像正在被解密 |

**配套**：
- 评分分数加 `ratingPop` 弹跳反馈。
- 全部效果在 `prefers-reduced-motion: reduce` 下关闭（无障碍底线）。

### 设计约束（为什么只加这 5 个）
- **不加彩色光效**：全站是黑白档案美学，加霓虹会立刻掉档。
- **不动布局**：所有效果只用 `animation` / `opacity` / `transform` / `filter`，不产生重排。
- **性能边界**：颗粒动画每秒只重绘 2.5 次（4 段跳变），且 `steps(1)` 不做插值；标题解码对 > 42 字的标题**自动跳过**，避免长标题闪烁成噪声。
- **可回退**：每个效果都是独立选择器，删掉对应 CSS 即可，不影响功能。

## 10. 第六轮：滚动视差 + 鼠标探照灯

| # | 效果 | 实现 | 观感 |
|---|---|---|---|
| 1 | **列表页头图滚动视差** | `initParallax()`：scroll 时把 `-rect.top / height` 归一化到 ±1，写入 `--lhp`（±18px），由 `::before` 的 `translate3d + scale` 消费 | 滑动列表时头图像隔着一层玻璃缓缓错动，不再死贴在页面上 |
| 2 | **鼠标跟随探照灯** | `initSpotlight()`：720×720 的柔光层，`translate3d` 跟随并带 0.14 缓动（有「灯罩惯性」），`mix-blend-mode: screen` | 暗色页面上像有一盏手电随鼠标扫过档案柜 |

**两个踩过的坑（记下来防止回退）**：
- **层级**：定位元素 `z-index: 0` 会绘制在普通文档流内容**之上**，探照灯会冲淡文字。改用 `z-index: -1` 沉到正文之下、底色之上，`#app` / `#main-content` 都没有不透明背景，所以能透出来。
- **悬停规则会覆盖位移**：原 `.list-header:hover::before { transform: scale(1.05) }` 会把视差位移抹掉。已改成同样带 `var(--lhp)` 的写法，只放大缩放值（1.08 → 1.12）。

**性能**：探照灯只改 `transform`（合成层，不重绘）；视差用 `requestAnimationFrame` 节流，并跳过视口外的头图。

**降级**：触摸设备（`hover: none`）、`prefers-reduced-motion` 下探照灯不创建、视差归零。
