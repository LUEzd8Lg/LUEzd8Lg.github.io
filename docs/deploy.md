# 发布上线 · 部署方案

> 目标：你在后台传档案，别人的手机/电脑打开网址就能看到。

---

## 当前选定路线：GitHub 托管（无服务器）

**结论：不买服务器，用 GitHub 仓库当后端。**
后台改完 → 提交到仓库 → GitHub Pages 自动重建 → 所有人可见。成本 0，维护 0。

### 一次性配置（只做一次）

1. GitHub → Settings → Developer settings → **Fine-grained PAT**
   - Repository access：只选你这一个仓库
   - Permissions：**Contents = Read and write**（其余全不给）
   - 生成后复制令牌（只显示一次）
2. 站内 → 侧边栏「我的账户」→ **云同步** → 填 Owner / Repo / PAT → **保存配置**
   - 这个令牌同时用于：数据备份、**排版原件上传**
3. 确认 Pages 已开启：仓库 Settings → Pages → Source = `main` 分支根目录

### 日常发布流程

| 步骤 | 操作 |
|---|---|
| 1 | 进 **管理后台** → 档案管理 → 新增 |
| 2 | 填标题 / 分类 / 摘要 / 标签 |
| 3 | （可选）**排版原件** 点「上传」选 HTML → 自动提交到 `data/dossier/` |
| 4 | 正文框粘贴纯文字版（供搜索与手机阅读） |
| 5 | 保存 → 回「同步」页点 **↑ 上传到云端** |
| 6 | 等约 1 分钟 Pages 构建完成，手机刷新即可看到 |

> 第 5 步就是「发布」动作。没有它，改动只存在你浏览器里。

## 一、关于「我的文档有排版」怎么办

**结论：docx 的排版无法自动保留，正确做法是「排版原件 + 结构化正文」两条腿。**

### 为什么不能靠自动转换

站内换 docx 用的是 mammoth.js，它是**语义转换器**：只认「标题样式 / 列表 / 表格 / 图片 / 加粗」，
**主动丢弃**字体、字号、颜色、页边距、页眉页脚、分栏、艺术字、文本框、印章贴图定位。
你那份 `老鸹岭地下结构·AE-0001-附07` 是**设计过的档案页**（牛皮纸底、印章、地图、图版位），
过一遍 mammoth 会变成一堆朴素段落 —— 排版全毁。

### 正确做法：排版原件用 iframe 原样嵌入

站点已支持 `dossier` 字段：详情页会把**整份 HTML 原样嵌进页面**，版式与原件 100% 一致。

```
entry.dossier = "data/dossier/老鸹岭地下结构·AE-0001-附07.html"
```

前提：**这份 HTML 必须是自包含的**（CSS 内联、图片用 base64 或内联 SVG、不引用外部文件）。
你现有的那份正好符合 —— 我查过，它的贴图与地图全是内联 SVG，没有外部依赖。

若是 .docx 且没有 HTML 版：用你已有的 `_build_laogualing/build_docx.py` 那套流程产出 HTML，
或者 Word「另存为网页（单个文件）」。**不要直接传 docx 进详情页**。

### 为什么还要一份纯文字正文

iframe 里的内容**搜索引擎读不到、站内搜索搜不到、手机排版会横向滚动**。所以：

- **排版原件** = 给读者看的「原件感」（放在详情页顶部）
- **结构化正文** = 给搜索/评分/引用/手机读的（放在下方）

两者都填，是这个站最舒服的形态。

## 二、为什么放弃「真实后端」

| 对比 | GitHub 托管 | 自有服务器 |
|---|---|---|
| 成本 | ¥0 | ¥30–100/月 + 域名 |
| 维护 | 无 | Node 常驻、备份、HTTPS、备案 |
| 别人能看到你的更新 | ✅ 构建后生效（约 1 分钟） | ✅ 即时 |
| 数据丢失风险 | 极低（Git 有完整历史） | 需自己做备份 |
| 多人同时投稿 | ❌ 只有你能改 | ✅ |
| 评论/评分跨设备 | ❌ 仍是本机 | ✅ |

**结论**：只做「你一个人发内容、大家阅读」，GitHub 完全够用，而且顺带得到了版本历史 —— 每次改动都能回滚。

如果以后要开放多人投稿/全站评论，再上服务器，前端代码不用重写（`API` 层已双模）。

## 三、上线前检查清单

- [ ] GitHub PAT 已配置，Contents 权限为读写
- [ ] 后台「上传到云端」能成功（看状态提示）
- [ ] 手机 4G 网络打开 Pages 地址，能看到刚发布的档案
- [ ] 排版原件的 iframe 在手机上能正常显示（必要时点「新窗口打开」）
- [ ] `data/dossier/` 下文件不超过 4MB/个
- [ ] 管理员密码不是默认 `admin123`（纯前端模式下管理员密码只在本机校验，但仍建议改掉）
- [ ] 想清楚是否保留登录墙（见下文）

## 四、还有个「体验」问题，建议一起改

现在访客第一次打开会**撞上登录门禁**（可点游客模式进入）。
SCP 这类粉丝站是**公开阅读**的，登录墙会劝退大部分人。

建议改成：**读完全公开，评分/评论/投稿才要登录**。
改动不大，但对「发出去」的转化率影响很大。

## 五、备选：真要上服务器时

如果后续需要多人投稿、跨设备评论评分、即时生效，再按下面走（代码已就绪，无需重写前端）：

| 方案 | 成本 | 说明 |
|---|---|---|
| 海外 PaaS（Railway / Render） | $0–5/月 | 最省事，注意**必须挂持久磁盘** |
| 香港/新加坡 VPS | ¥30–60/月 | 免备案，数据在自己手里 |
| 大陆服务器 | ¥40–100/月 | 需 **ICP 备案**（1–3 周） |

届时要点：
- `server/.env` 改 `ADMIN_PASS`、`JWT_SECRET`
- 数据在 `data/*.json`，**必须有持久磁盘**，否则重启丢档
- 服务器会动态生成 `/data/merged.js`，后台上传即时对所有人生效
- 别忘了 `SMS_PROVIDER`/`EMAIL_PROVIDER` 若仍为 mock，注册验证码会直接显示在页面上
