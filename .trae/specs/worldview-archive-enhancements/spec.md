# 世界观察档案库 · 全面增强规格文档 v1

## 一、问题陈述（Problem）

当前世界观察档案库已具备基础的档案浏览、投稿、审核功能，但在以下五大维度存在明显短板：

1. **数据链路不可靠**：管理员审核通过的投稿条目未自动同步渲染到对应分类列表，用户感知不到审核生效
2. **搜索能力有限**：当前搜索仅覆盖标题/编号/摘要，缺少正文、标签模糊匹配及高级筛选
3. **数据安全缺失**：所有数据存于 localStorage，缺乏一键备份导出机制
4. **长文档阅读体验差**：缺少目录导航（TOC）、字号调节受限、无阅读进度记忆
5. **视觉统一性不足**：无封面的档案使用 SVG 占位，缺少专属页头横幅、favicon、404 页等氛围元素
6. **社交功能空白**：无收藏/书签、评论/批注、关联推荐、草稿箱等用户粘性功能
7. **管理员后台简陋**：缺数据仪表盘、操作日志，批量操作只支持删除
8. **可访问性不足**：无键盘快捷键、无明亮主题切换、移动端适配不完整

## 二、目标用户（Users）

| 用户角色 | 描述 | 核心诉求 |
|---|---|---|
| 访客（LV.1） | 游客身份浏览档案 | 流畅阅读体验、快速检索、移动端适配 |
| 注册用户（LV.2） | 已登录普通用户 | 投稿、收藏、评论、草稿自动保存、阅读进度记忆 |
| 管理员（LV.9） | admin 账号 | 批量审核、操作追溯、数据统计、一键备份导出 |

## 三、目标与非目标（Goals / Non-Goals）

### 3.1 目标（Goals）

1. **修复核心数据链路**：管理员审核通过后，投稿条目立即出现在对应分类列表中，并刷新档案计数
2. **提升搜索命中率**：搜索范围扩展到正文、标签、代号，支持高级筛选（分类、等级、时间）
3. **数据可导出**：管理员后台一键导出 JSON 备份（含档案、用户、投稿、覆盖层）
4. **长文档目录导航**：详情页自动生成 TOC 目录，支持锚点跳转
5. **键盘快捷操作**：Esc 关闭弹窗、/ 聚焦搜索、←→ 列表翻页
6. **双主题切换**：默认暗黑（现有）+ 新增明亮档案室模式，状态持久化
7. **移动端适配**：卡片、投稿编辑器、管理员后台在 375px~768px 宽度下可用
8. **统一视觉占位图**：无封面档案使用统一黑白机密档案风格占位图（生图）
9. **分类横幅与 favicon**：5 大分类 + 管理员后台各配专属页头横幅，生成分辨率合适的 favicon
10. **自定义 404**：档案缺失风格的 404 页面
11. **档案收藏**：LV.2+ 用户可收藏，在个人中心查看列表
12. **评论系统**：详情页底部评论，管理员可删除
13. **阅读进度记忆**：长文档自动记录滚动位置，下次打开自动恢复
14. **关联推荐**：详情页底部基于标签/分类推荐相关档案
15. **投稿草稿箱**：未提交内容自动保存（localStorage），下次打开可恢复
16. **管理员批量操作**：批量通过/批量退回投稿（UI 已有，补齐逻辑确认）
17. **管理员操作日志**：记录审核/增删改操作，可按时间/管理员筛选
18. **数据统计仪表盘**：后台首页显示总档案数、待审核数、本月新增、用户增长曲线

### 3.2 非目标（Non-Goals）

1. **不引入真实后端数据库**：继续使用 localStorage 降级模式为主，Node.js 后端为可选增强
2. **不做真实用户通知推送**：仅站内通知（localStorage 持久化），不接短信/邮件
3. **不做 Markdown 编辑器**：保持现有所见即所得富文本编辑器
4. **不做多语言**：仅简体中文 + 英文标签，无 i18n 切换
5. **不做 SSR/SEO 优化**：保持纯前端 SPA 架构

## 四、功能需求（Functional Requirements）

### 4.1 内容与数据

#### FR-1 审核后数据同步
- 管理员调用 `adminReview(..., 'approved', ...)` 成功后：
  - 立即将条目写入目标分类的 `DATA[cat]` 数组（通过 `LocalEntries.add` 已实现，需确认 UI 刷新）
  - 刷新顶部状态栏「在档条目」计数
  - 若用户停留在对应分类列表页，自动 re-render 列表
- rule：审核通过后，打开对应分类页应能看到新条目（刷新/不刷新页面均生效）

#### FR-2 搜索增强
- **全局搜索框 & 搜索结果页**搜索范围扩展：`id / code / title / summary / body / tags / org / era`
- 搜索结果高亮关键词（body 取匹配片段前后 40 字 + `<mark>` 高亮）
- 列表页工具栏新增「高级筛选」折叠面板：
  - 分类多选（异常/组织/神祇/纪元/时间线）
  - 危险等级单选（safe/euclid/keter/thaumiel/apollyon/neutral）
  - 标签输入（逗号分隔 AND 匹配）
  - 时间范围（创建/归档日期区间，可选）
- rule：搜索"收容"可命中正文含收容的档案；选择等级=keter 后只显示 keter 条目

#### FR-3 数据导出/备份
- 管理员后台新增「数据」Tab 或在「档案管理」Tab 头部加导出区域
- 导出按钮一键下载 JSON：
  - 结构：`{ meta: { exportedAt, version }, categories, DATA: {...}, users, submissions, localEntriesOverrides, dismissedNotices }`
  - 文件名：`wa-backup-YYYYMMDD-HHMMSS.json`
- 可选：提供导入 JSON 恢复按钮（需二次确认 + 覆盖策略）
- rule：点击导出后浏览器下载 JSON 文件，打开文件可见完整数据结构

### 4.2 交互体验

#### FR-4 详情页 TOC 目录
- `renderEntry()` 渲染后，扫描 `detail-body` 内所有 `<h1>/<h2>/<h3>/<h4>` 标签
- 为每个标题自动生成稳定 id（slugify 标题文本，重复则加 `-2/-3`）
- 在详情右侧（或小屏顶部）渲染 TOC 侧边栏：
  - 按层级缩进显示
  - 当前滚动位置对应标题高亮（IntersectionObserver）
  - 点击标题平滑滚动到对应位置
- rule：详情页有 ≥3 个小标题时，TOC 自动出现；点击跳转且 URL hash 更新（可选）

#### FR-5 键盘快捷键
全局 `keydown` 监听，避免与输入框冲突：

| 快捷键 | 作用 | 触发条件 |
|---|---|---|
| `Esc` | 关闭当前弹窗/全屏编辑器/审核面板 | 任何弹窗打开时 |
| `/` | 聚焦顶部 #global-search 搜索框 | 非输入/textarea 聚焦时 |
| `←` / `→` | 列表页上一页 / 下一页 | 在列表页且非输入框 |
| `Ctrl+S` | 投稿页保存草稿（替代默认保存网页） | 投稿页 |
| `Ctrl+B` | 收藏/取消收藏当前档案 | 详情页且已登录 LV.2+ |

- rule：在任何页面按 `/`，光标跳到搜索框并选中全部内容

#### FR-6 暗黑/明亮主题切换
- 新增 CSS 变量集 `.theme-light`（明亮档案室模式：米白背景、深灰文字、暖银边框）
- 顶部导航右侧新增主题切换按钮（🌙/☀️ 图标）
- 用户选择持久化到 `localStorage` key：`wa_theme_v1`（`dark`/`light`）
- 初始值：跟随系统 `prefers-color-scheme`，用户手动切换后覆盖
- rule：切换主题后所有组件颜色正确变化，刷新页面保持选择

#### FR-7 移动端适配
断点：`<=768px`（平板/手机）

- 顶部导航：汉堡菜单展开收起（或 flex-wrap 自动换行 + 缩小字号）
- 卡片：`grid-template-columns: 1fr` 单列，左图右文保持（图片宽度 100px 或 30%）
- 投稿编辑器：工具栏换行，预览区默认收起，全屏按钮可用
- 管理员后台：表格横向滚动可滑动，按钮缩小，Tab 横向滑动
- 详情页 TOC：移到正文顶部作为折叠面板

- rubric：在 Chrome DevTools 375px × 667px 视口下人工检查 (0-2)
  - 2：所有页面无水平溢出，操作按钮可点击（≥40px 触达区），投稿编辑流程可完整走通
  - 1：个别页面有轻微溢出或按钮过小，不影响核心流程
  - 0：多个页面不可用

### 4.4 功能扩展

#### FR-12 档案收藏/书签
- localStorage key：`wa_favorites_v1`，结构 `{ [userId]: Array<{cat, id, addedAt}> }`
- 详情页头部机密印章旁或返回链接下方加「♡ 收藏」/「❤ 已收藏」按钮
- 个人中心（账号管理面板新增 Tab）显示收藏列表：
  - 每条显示分类、编号、标题、收藏时间
  - 支持取消收藏
  - 按收藏时间倒序
- 权限：LV.2+ 可用，LV.1 游客点击提示登录
- rule：点击收藏后刷新页面仍显示已收藏状态，个人中心列表可跳转

#### FR-13 评论/批注系统
- localStorage key：`wa_comments_v1`，结构 `{ [cat+':'+id]: Array<{id, userId, userContact, content, at, deleted}> }`
- 详情页底部（`detail-footer` 之前）新增评论区：
  - 评论总数徽章
  - 已登录 LV.2+ 显示输入框（多行 textarea）+ 提交按钮
  - 评论列表：头像占位 + 用户名 + 时间 + 内容
  - 管理员评论旁显示「删除」按钮（软删，内容显示「[已删除]」）
  - 管理员可删除任何评论，用户可删除自己评论
- rule：提交评论后立即出现在列表，刷新仍在；管理员点击删除可移除

#### FR-14 阅读进度记忆
- localStorage key：`wa_read_progress_v1`，结构 `{ [cat+':'+id]: { scrollY: number, at: number, fontSize: string } }`
- 详情页滚动时 debounce 保存 `window.scrollY`（300ms）
- 进入详情页时，若存在进度记录且 `at` 在 30 天内：
  - 显示 Toast：「检测到上次阅读位置，是否恢复？ [恢复] [忽略]」
  - 用户确认后平滑滚动到保存位置
  - 同时恢复字号（detail-font-size）
- rule：打开一篇长文档滚到中间，关闭页面再打开，提示恢复，确认后回到原位

#### FR-15 档案关联推荐
- 详情页底部（评论区之前）新增「相关档案」区块
- 算法（按权重排序取前 6）：
  1. 同分类 + 同标签 ≥1 个（高权重）
  2. 同分类（中权重）
  3. 标签交集 ≥1（低权重）
  4. 排除当前档案自己
- 展示卡片：与首页精选文档卡片风格一致（左图右文缩略卡）
- rule：任何有 ≥2 个标签的档案，其详情页底部能看到至少 1 条相关推荐

#### FR-16 投稿草稿箱
- localStorage key：`wa_drafts_v1`，结构 `{ [userId]: { title, category, class, summary, body, tags, source, cover, savedAt } }`
- 投稿页 `renderSubmit()` 渲染完成后：
  - 自动检测是否有未提交草稿，若有则弹通知「检测到未提交的草稿，是否恢复？ [恢复] [丢弃]」
  - 用户输入时 debounce 每 5 秒自动保存一次（或按 Ctrl+S 立即保存）
  - 投稿成功提交后自动清除草稿
- 投稿页顶部加「草稿箱状态」提示（已保存时间、手动保存按钮、丢弃按钮）
- rule：编辑一半关闭页面再打开，提示恢复，确认后内容完整回来

- UI 已存在（`#admin-subs-batch-approve` / `#admin-subs-batch-reject`）

- 管理员后台默认 Tab 改为「仪表盘」（原 Tab 顺序：仪表盘 → 投稿审核 → 档案管理 → 用户管理 → 操作日志）

  2. **待审核投稿**：实时数量 + 快捷跳转按钮
  3. **本月新增档案**：按日期统计 30 天新增数量柱状图（纯 CSS / Canvas 简易柱状）
  4. **用户增长曲线**：按注册日期统计 30 天新增用户 + 总用户折线图
  5. **分类占比饼图**：可选 Canvas 简易环形图
- 快捷操作区：「一键导出备份」「去审核投稿」「新增档案」按钮
- rule：管理员登录进入后台，第一眼看到以上 4+ 个统计卡片，数字与实际数据一致

## 五、非功能需求（Non-Functional Requirements）

### NFR-1 性能
- 列表搜索：1000 条档案内搜索响应 < 150ms（debounce 250ms 后）
- TOC 生成：50 个标题以内 < 50ms
- 所有新增 localStorage 读写加 try/catch，配额溢出时静默降级
- 生图资源使用 WebP 或压缩 PNG，单张横幅图 ≤ 300KB

### NFR-2 兼容性
- 目标浏览器：Chrome 90+ / Edge 90+ / Safari 14+ / Firefox 88+
- ES6+ 语法（不使用 import/export，保持现有单文件 IIFE 结构）
- Canvas 功能（思维导图、图表）使用 2D Context，不依赖 WebGL

### NFR-3 可维护性
- 所有新增功能尽量保持在 `app.js` IIFE 内部，按注释分区（与现有 `// ============ XXX ============` 风格一致）
- 新增 CSS 变量放在 `:root` 或 `.theme-light` 内，按功能分组注释
- localStorage key 全部使用 `wa_*_v1` 前缀，便于后续版本迁移

### NFR-4 安全性
- 所有用户生成内容（评论、投稿正文、标签）在渲染时经过 HTML 转义或白名单 sanitize
- 管理员操作日志不可被前端修改（只读展示，写入仅在 admin 成功回调）
- 草稿、收藏、评论按用户隔离（`userId` 作为 key 前缀）

### NFR-5 视觉一致性
- 所有新增按钮、徽章、卡片样式复用现有 CSS 类（`btn`、`ec-badge`、`entry-card` 等）
- 明亮主题保持 SCP 档案室气质，不做花哨配色
- 生图素材必须是黑白/冷灰色调，符合现有视觉体系

---

## 六、约束与假设（Constraints & Assumptions）

### 6.1 约束
1. **技术栈约束**：继续使用原生 HTML/CSS/JS（IIFE），不引入 React/Vue 框架
2. **存储约束**：localStorage 约 5MB 上限，评论/日志若无限增长需考虑分页+截断
3. **生图约束**：占位图/横幅图必须通过 text_to_image API 生成，不可使用外部网络图片版权素材

### 6.2 假设
1. 用户可接受「草稿、评论、收藏存本地 localStorage，清理浏览器数据会丢失」的前提
2. 管理员账号（admin/admin123 默认）的安全性由使用者自行负责
3. Node.js 后端可选启动，所有功能在降级 localStorage 模式下同样可用
4. 生图 API 可调用，生成的图片可下载保存到本地 `data/` 目录

## 七、开放问题（Open Questions）

1. **Q1**：是否需要支持数据导入恢复？（规格中列为可选，若用户确认则实现完整导入覆盖逻辑，否则只做导出）
2. **Q2**：评论是否需要管理员审核后显示？（规格默认即时发布+管理员可删，若需审核则改流程）
3. **Q3**：明亮档案室模式下，是否保留噪点/扫描线暗纹背景？（建议保留但降低透明度，保留氛围）
4. **Q4**：用户数据隔离基于 contact 还是自增 userId？（当前 localStorage 无自增 id，建议基于 contact 字符串，后续可迁移）
